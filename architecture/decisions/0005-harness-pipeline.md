# 0005: Harness pipeline

Status: accepted, 16 October 2026; revised for the NEU-111 fixed-shape trial, 4 November 2026, and for NEU-148's lane assignment and agent dispositions, November 2026. The [owner's decisions](../../process/decisions.md) govern product meaning. With its settings off, a review runs the trial; the section readings, code's decisions and per-batch publication below are the target.

## Decision

A review runs Precompute, then, side by side: the front task (Frame, then Map); four finder tasks, which start when Frame lands; the two section readings, which start as soon as Precompute has planned them; and code fill. Verify checks each finding as it is recorded. Code then decides each section's lane, the units and their dispositions, and publishes settled batches. The [native task record](0014-ace-style-pi-harness.md) defines execution ownership. Records keeps retained outputs and the published packet.

| Work                   | Shape                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Precompute             | Code reads the immutable range, scope and prepared retrieval leads. Cached coverage remains available if enrichment stops.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Frame                  | One no-tool context states the goal and up to five done-when conditions. Code checks citations, assigns condition IDs and supplies a disclosed fallback.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Map                    | One no-tool context groups a bounded manifest by entry IDs. Code expands those IDs and ensures every retained file and hunk belongs to one group.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Find                   | Four independent contexts look for scope fit, correctness, risky edges and tests. Each opens with a structured diff by section, bounded in size, with deleted lines shown and every handed-over line citable, and reads more through a lookup that takes many ranges. Each records at most five findings and reads at most 200,000 characters. Code places each finding by its primary hunk.                                                                                                                                                                                                                                                                               |
| Verify                 | Each distinct finding is checked once, keyed by its claim, in a fresh context with evidence inlined by code and no lookup tools, as soon as it is recorded. The finder then deduplicates; a check made redundant keeps its fate. Findings from Lane review go through the same Verify.                                                                                                                                                                                                                                                                                                                                                                                     |
| Assess and Lane review | Every section is read twice, in reading groups packed by code, riskiest first and up to the run's cut-off, without delaying a finder. Assess asks whether a section needs a person: both axes with cited evidence, requirement names, impact and gaps, never seeing the lane, the floor or the goal. Lane review asks whether it is right: a verdict per section, comments and what was checked, never seeing the lane or Assess's answer. Assess has two turns, the second only to resend a refused answer; Lane review has three, the first for lookups. A reading that fails, is refused or is orphaned ends as not judged for its sections and never fails the review. |
| Decide                 | Code sets each section's lane with lane rule 3: `laneOf` over the recorded assessment, then the public-surface raise, then the code risk floors, so a floor only raises. Code adds its own gaps, sets proof state from proof records, forms units as a file's sections that share a lane, and gives dispositions through `applyLane`. Work no agent could judge is human-required with the note "No agent decision in this run".                                                                                                                                                                                                                                           |
| Fill and Link          | Code fills every group's owned ranges while the finders run. Link attaches verified findings and writes a bounded digest. With the readings off, it derives only requests for changes from kept defects; with them, dispositions come from Decide.                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Publish                | One publisher appends settled batches to Records in the review's batch order, each publication a cumulative packet that supersedes the last. A batch is settled when every section has an applied lane and no finder or Verify claim can still reach it; once published, it is frozen for the review. Each publication's plan is decided once, as shared work keyed by the cycle, the run key and the previous packet, so a replay writes the same packets. A later review of the same range under another configuration publishes once, when complete. Every owned range remains covered.                                                                                 |

Frame and Map have one turn and one invalid-answer retry each. Their deadlines are 90 and 120 seconds after their respective starts. Each finder has eleven tool turns followed by a final generation. Its deadline is the earlier of 270 seconds after start and 75 seconds before the cut-off. A finder starts only when at least 90 seconds remain before that reserve. Verify has one turn and the run's cut-off. With the readings off, the valid-answer path uses at most 70 model calls: two front calls, four sets of twelve Find calls and twenty Verify calls. The readings add one Assess and one Lane review call per reading group and a Verify call per distinct Lane-review finding, so their number grows with the change; the run's cut-off bounds them. Invalid-answer retries can add calls.

A run lasts ten minutes and stops model work at 9:10, leaving time for code fill, Link and Publish. A review-owner abort publishes nothing. A cut-off retains stored findings, finished verification results and finished readings. A batch whose sections are all decided is published. A batch with a section not reached waits for a follow-on run, which reuses every stored computation, up to eight follow-on runs; once none is left, the section is human-required, cause `not-reached`. A provider quota refusal leaves its batches pending with a disclosed gap and asks for no follow-on run. Findings without verification become count gaps, never comments.

## Trial publication rules

With the readings off, the trial's rules hold: units without a kept defect have no disposition, unassessed units use human-suggested and not-assessed, kept risks and questions can add comments without a disposition, and Link never approves. With the readings, every unit in the human-suggested, agentic and static-automation lanes carries its lane's judgement, comments and disposition, and a unit no agent could judge is human-required with no suggested review. Lockfiles and declared-generated files form one code-only batch, which finders do not read. Files GitHub Linguist's pinned generated and vendored lists mark skip the model readings; the repository's own declarations override the lists both ways, and a mark never approves and is disclosed. The packet stays incomplete where assessment or verification is missing.

A person's decision carries to a unit whose sections are all unchanged since that decision, and closes it; a carried request for changes keeps its comments. Carried agent judgements and background model preparation stay off; NEU-148 brings them back before the open-source cut. Their Records event kinds and old packet readers remain available. When the readings are on, Graph's callers index is read when a commit is prepared. Precompute leads, scope freshness checks and the freshness judge remain in place.

The scope stratum stays an open product question. "Assess" and "Lane review" are the shown stage names for now. The [batch and unit record](0007-batches-units-lanes-and-cycles.md) distinguishes the trial from the established lane policy. Vocabulary and foundations require the owner's approval before their wording changes.

## Retained boundaries

Lookups read committed source, keep bounded results and treat repository text as data. Agent retries and provider retries remain bounded. No stored computation or completed execution grants approval. The [proof requirements](../../process/decisions.md#area-11-verification-and-review-delivery-19-october-2026) still require applicable evidence to agree before anyone treats a requirement as proven. Missing evidence reaches readers as a gap. A test's existence, or a test that calls the changed code, is a hint shown to a model as context, never evidence: it lifts no gap, lowers no lane and settles nothing.
