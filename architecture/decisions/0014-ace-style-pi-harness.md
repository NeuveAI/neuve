# 0014: Ace-style pi harness within Effect and Bun

Status: accepted by the owner on 28 October 2026. Implementation proceeds on `codex/pi-transition`; main stays unchanged until the owner completes a full integrated run and explicitly authorizes merging. The transition's Linear scope (NEU-50) holds workstream objectives, acceptance, ownership, and dependencies.

## Decision

Adopt Ace's harness structure and pi stack within Neuve's Effect and Bun platform. The source reference is `githubnext/ace` at `fe66277931d2c46f12dcc250b63e1b4428a4e9ee`. Pin its inspected `@earendil-works/pi-durable`, `pi-ai`, and `chord` versions initially. Preserve the MIT notice for adopted code. No dependency patches are introduced.

Use Ace's separation between runtime-neutral channel logic and host-specific capabilities. Under the [local runtime decision 12.59](../../process/decisions.md#area-12-ace-style-pi-transition-28-october-2026), pi owns agent execution on pi accounts and the unmodified Claude Code program owns the loop on Claude subscription accounts. Both sit behind the [runtime contract and account registry](0017-runtime-contract-and-accounts.md), which let callers name an account and read capabilities without selecting a runtime. Effect owns application services and resource lifetime around the host, Records, Graph access, provider sessions and telemetry. Bun remains the executable platform. The former manual agent loop and Effect Workflow do not return as a second scheduler.

The review task owns Precompute, the front task for Frame and Map, the reading plan and its Assess, Lane review and briefing tasks, and the batch waiters. The plan uses Map's existing batches. A Lane review task owns the checks of its defect claims. A batch waiter waits on the batch's readings and registered incoming checks, then hands its selected input to the publisher. Each agent step on a pi account owns its pi conversation. The [pipeline record](0005-harness-pipeline.md#decision) describes stage bounds and when batches can publish. Source identity, validation, ownership and computation reuse remain explicit. Records remains the authority for review facts and retained computation outputs. Graph remains behind `packages/graph-client`. The review desk continues to project Records. A completed execution never grants approval. On an account whose runtime runs its own loop, a review stage keeps its durable phases and drives one contract turn per round, reusing the stage policy functions. pi accounts keep the pi conversation, and pi is not wrapped in the contract: it registers as a status-only runtime. Claude stages are enabled. The [runtime contract record](0017-runtime-contract-and-accounts.md#how-review-stages-and-coding-chats-use-it) gives both paths, and why stages don't use the coding chats' bridge.

Tools, telemetry, logs, receipts, budgets and stage policy are shared above the normalized runtime event stream. Each runtime keeps its loop, retries, compaction, durable resume, native capture and credentials. The [runtime proposal's ownership split](../../process/proposals/claude-subscription-route.md#what-is-shared-and-what-each-runtime-keeps) defines that boundary. Runtime capabilities expose differences such as per-request telemetry, byte-exact capture and internal retries. Shared code reads those capabilities and final failures rather than repeating runtime mechanics.

New direct routes carry an account name and kind. Run configurations admit the Claude route. The [model-route record](0008-model-routes-and-budgets.md) preserves legacy frozen request JSON and default-account run keys, so account metadata does not restart completed work. Coding conversations retain pi ownership on pi accounts. On Claude subscription accounts, coding chats use Claude Code's own native conversation through the [chat bridge](../../packages/harness/src/chat-runtime/bridge.ts), under the conditions the [runtime contract record](0017-runtime-contract-and-accounts.md#how-review-stages-and-coding-chats-use-it) sets. This amendment builds only local sessions on the owner's host. Shared sandboxes and remote machines remain modeled with their sign-in and ownership questions open, as required by the [local-build scope in decision 12.59](../../process/decisions.md#area-12-ace-style-pi-transition-28-october-2026).

Records admission and pi execution use a stable shared request identity. Repeated admission and recovery reuse the recorded task and its owned conversations. Records publication has an idempotent identity and recoverable receipt. Each external effect declares its recovery behavior; an uncertain effect is disclosed rather than assumed absent or blindly repeated.

Coding sessions may write in their assigned worktree. Final-review sessions keep their restricted tools and frozen submitted source. Neither may inherit the other's capabilities accidentally. Replay reviews remain isolated from labels, later revisions, research notes, and credentials.

The workspace is the collaborative home for connected repositories, projects and coding sessions. `bun workspace` opens it with the LaCie storage profile and the current directory as its initial project. Storage and project overrides remain explicit options. Opening the workspace requires no commit hash, clean checkout or named branch. Submitted review ranges and validation receipts retain their own commit identities, as required by [decision 12.7](../../process/decisions.md#area-12-ace-style-pi-transition-28-october-2026).

The host keeps Ace's default tailnet participation when Tailscale is running. `--loopback` opts out of tailnet listeners, discovery, directory and lobby watching. A dynamic host port selects an independent free HTTPS port, and its advertised URL uses the actual bound port, following the owner's [tailnet launch decision 12.14](../../process/decisions.md#area-12-ace-style-pi-transition-28-october-2026).

[Decisions 12.8 and 12.9](../../process/decisions.md#area-12-ace-style-pi-transition-28-october-2026) retain Ace's dashboard, channels, chats, issues, pull requests and continued agent work in Ace's actual application and styling. The owner's 31 October direction confines Neuve's design system to its independent review UI and supersedes earlier visual adaptation instructions. Standalone reviews remain available. Host adapters resolve external items to immutable submitted source and attributed context; Records retains their associations with review cycles and exact source revisions. Pi owns coding conversations on pi accounts; Claude subscription accounts are to use Claude Code's native conversations, as the [runtime contract record](0017-runtime-contract-and-accounts.md#how-review-stages-and-coding-chats-use-it) describes. Provider checks, issue completion, merged pull requests and completed runs never become dispositions. New Linear account setup remains deferred.

## Captures and evaluations

Telemetry and complete session and dataset exports are part of this transition and are required for the next quality climbs. The one exception is a call whose capture can't be written. It goes ahead once the call's retries run out, and its export names the gap as capture loss and never reads as complete. The [owner's capture-loss ruling, decision 17.63](../../process/decisions.md#agents-across-channels), amends 12.2 for this case. The [candidate evaluator](../../packages/evaluation/src/candidate/capture.ts) never scores such a capture. Native capture stays inside each runtime. Pi's native database beneath the review run folder owns live pi execution history. Before that folder is removed, export its history and request journal to masked raw-capture blobs in Records, joined to Neuve's stage, lead, unit, source, and publication identities. Records does not mirror or schedule live pi tasks. [The persistence record](0004-persistence-and-range-immutability.md#pi-review-execution-and-capture-lifetime) defines capture-before-removal, raw retention, and separate retained computation outputs. Claude stage capture records each contract context as declared observations with no wire capture, which the [capture dump](../../packages/harness/src/pi/capture/dump.ts) accepts, and the [candidate evaluator](../../packages/evaluation/src/candidate/capture.ts) refuses to score it because it holds no wire evidence. Claude stages make no byte-exact replay claim. Shared logs, receipts and usage are to consume normalized contract events. Evaluations requiring exact replay stay on pi, following the [runtime proposal's telemetry and replay limits](../../process/proposals/claude-subscription-route.md#what-is-shared-and-what-each-runtime-keeps). Pi's capture safety, retention and publication requirements stay intact.

The owner's [raw-capture decision 12.12](../../process/decisions.md#area-12-ace-style-pi-transition-28-october-2026) preserves byte-exact `native/pi.sqlite`, the raw journal and `.original` files with their inspection and certification. Sanitized exports continue to apply parsed-string masking and credential protection. Existing retention and inspection requirements remain; simplification stays within raw preservation.

Record the effective request after hooks, offered tool definitions, available provider responses, per-turn usage and timestamps, tool calls and results, child sessions, compactions, interrupted partials, external output artifacts, and every lead's fate at handoffs. Capture actual wire requests where the provider permits it. Mask parsed strings in sanitized exports without altering model input or corrupting serialized JSON. Never store credentials or claim access to hidden provider reasoning. Existing raw-capture retention and retained-output distinctions remain authoritative.

Managed review and coding captures attempt to register private keyed credential detectors before each authenticated dispatch, after the headers are resolved. Under the [channel credential-loss ruling, decision 17.66](../../process/decisions.md#agents-across-channels), which is provisional until the owner confirms it, a channel call goes ahead after registration writes exhaust their retries. Only an unregistered credential stops its call, and only when its loss can't be recorded in the fixed reserve. A lost line for a credential the private authority registered is an ordinary loss in `capture-loss.json`, and it never stops the call. The [export scan](../../process/decisions.md#area-12-ace-style-pi-transition-28-october-2026) scans every credential the private authority holds, and it holds a capture with a recorded unregistered credential until it identifies the credential and certifies the capture clean. A missing or damaged reserve also holds the capture when the journal requires it. A crash with an intact reserve and no registration loss leaves the interrupted-session gap. The [private inspection authority](../../packages/harness/src/pi/capture/private-inspection.ts) persists a generated key and authenticated recognition metadata outside native storage, journals, spill, datasets, logs and model inputs. It retains no provider credential strings. The existing source owner opens it before the native producer and keeps it through terminal capture. A restart reopens that authority; missing or corrupt historical metadata cannot be replaced with a new empty authority. Copying a session to another machine requires separate private authority handling; session exports never carry it. Explicit ephemeral provider use makes no restart guarantee.

The [whole-source inspection policy](../../packages/harness/src/pi/capture/safety.ts) covers exact string code units, original valid-UTF8 journal payload frames, original artifact and backup bytes, and complete SQLite cells. It checks raw UTF8/UTF16 representations and nested JSON quoted tokens, including earlier duplicate properties. Raw numeric matches are protective even where the earlier JSON-string-only inspector accepted them. Recipe 6, portable source validation 10, and credential certificate 3 record this interpretation; older portable evidence is insufficient. Equal recognition material shares an epoch while every dispatch retains its registration obligation. Journal certificates inspect their own planned bytes before append and bind canonical non-certificate administration separately, avoiding a self-referential whole-journal hash. This is a trusted producer protocol, not cryptographic proof that arbitrary rewritten certificates establish absence.

An authenticated call killed before its original observation completes can receive an explicit retained-prefix certificate only when its registered pending call belongs to an earlier unclosed journal session. It never receives a fabricated observed, end or close fact. The [shared retained SDK adapter](../../packages/harness/src/pi/capture/retained-sdk.ts) runs the installed pinned response assembler offline for both credential inspection and provider comparison. It copies scalar strings and every generated object property name synchronously at every SDK emission and original frame boundary, including nested repaired argument keys, superseded partials and silent signature changes before cleanup. Keys and values share the existing depth and aggregate work bounds. Publication inspects these generated views for every authenticated SDK model stream, including completed and observed calls. Observation and interruption facts establish lifecycle coverage, never the safety of generated views. Unknown authenticated model-stream assemblers make inspection unavailable; count-token artifacts remain separate because they are not model streams. The request records versioned original provider-input messages and whitelisted model semantics, bound to its call identity. Historical custom-tool calls without this context remain unavailable. Portable reasoning retains containers and discriminators, and comparison recognizes declared withheld thinking while continuing to compare other content. Finite input and generated-work budgets bound inspection, with cooperative checks during parent input scanning. The parent handles cancellation and one close allowance sized once from the recorded inventory ([decision 12.26](../../process/decisions.md), the [close watchdog](../../packages/harness/src/pi/capture/watchdog.ts)), shared by census, projection, SDK replay, sealing and readback and capped at four hours; it then terminates and awaits the SDK worker when inspection closes. Credential detection runs in a scoped pool of at most four Bun workers, with serial fallback, bounded queueing and one authority check after the workers join. Synchronous parent input and context validation before worker dispatch cannot be preempted by that timer. The current `pinned-sdk-assemblies-v4` policy is part of `POLICY_SOURCE`, so earlier certificates cannot certify this interpretation. Portable prefix declarations come only from validated restricted certificates. The [portable archive validator](../../packages/harness/src/pi/capture/archive.ts) requires that policy in the embedded original restricted manifest and binds the prefix declarations to that manifest and the portable projection inventory. The [provenance validator](../../packages/harness/src/pi/capture/provenance.ts) also binds them to the carried interrupted call identities. Relabelling outer metadata cannot upgrade an older portable capture whose original source lacks the policy. Re-export requires inspection of the original sources under the current policy. The interruption gap remains, so this does not make a killed run complete or eligible for scoring. These fields retain private recipe 6 and credential certificate 3, with portable source validation 10.

The [actual provider SDK call sites](../../packages/harness/src/pi/providers/agent-route-provider.ts) also freeze versioned sparse invocation options and Anthropic OAuth mode. Captured empty options mean the SDK received no semantic options; missing historical options remain unknown. Replay also requires an explicit captured cache-retention option because an omitted value can depend on uncaptured environment state. Wire-payload rewrites do not establish wrapper-local options such as effort or requested service tier. A separate `sdk_invocation_end` event records the actual signal state and callback count through the existing private credential authority and public masking path. A signal-aborted call whose normalization boundary is unresolved cannot support exact SDK replay. Callback-thrown failures are distinct from signal cancellation. An interrupted prefix may support conservative scalar inspection without creating an original terminal message, end, observed or not-aborted fact.

Inspection exhaustion, cancellation, unknown history and unsafe observations refuse exact export while retaining the original source. Unsafe observation facts are appended before their sanitized copies. A killed process keeps its interruption gap even after safe continuation. The existing object and dump limits remain 512 MiB and 4 GiB; inspection has additional explicit work, nesting and validation bounds, including a 64 MiB untrusted JSON value ceiling during close. These bounds are safety limits, not proof that every source under the dump limit can finish inspection.

The existing datasets on the research volume (kept privately) supply the baseline. Keep their archives and labels immutable. At the end of the port, run fresh scored candidate reviews into separate directories and compare them with that baseline using the established measures. Recomposition is not a fresh review. Reasoning-summary reading runs remain analysis-only and are never scored. Runtime migration does not also change ranking, prompts, retrieval configuration, or stack-source enablement.

## Optional Linear scope

The Linear planning workstream (NEU-59) holds its scope, acceptance, and implementation status. This boundary adds source selection to the existing coding workspace. It does not add Plan, Browse, or Browser Preview panels or change the independent review path when planning is absent.

The [trusted integration schema](../../packages/harness/src/integrations.ts) reads `integrations.json` beside the user's Neuve settings, outside the repository. On macOS this is `~/Library/Application Support/Neuve/integrations.json`. It never reads repository `.mcp.json`. The version remains `1`; `servers` maps a connection ID to its transport, permitted variables, read-only tool allowlist, identifier fields, and optional `fetch` and `planning` mappings.

| Configuration | Meaning |
| --- | --- |
| `transport` | An absolute stdio `command` with optional `args` and `env`, or an HTTP `url` with optional `headers` |
| `variables` | The only environment variable names allowed in `${NAME}` expansion |
| `tools` | The explicitly permitted read-only operation names from the inspected bridge catalog |
| `identifiers` | Response field names classified as `key`, `url`, `person`, `email`, or `id` |
| `fetch` | A permitted `tool`, its key `argument`, and optional `keyPrefixes`, used by cycle scope discovery |
| `planning.sourceSchema` | `linear-v1`, the supported issue and page response interpretation |
| `planning.search` | A permitted `tool`, `queryArgument`, optional `cursorArgument`, and optional scalar `fixedArguments` |
| `planning.issue` | A permitted `tool`, `idArgument`, and optional scalar `fixedArguments` |
| `planning.dependencies` | A permitted `tool`, `idArgument`, optional `cursorArgument`, and optional scalar `fixedArguments` |

Every mapped operation must appear in `tools`. The trusted owner verifies the real operation names, input schemas, response shapes, read-only behavior, and continuation arguments before enabling them. A configured connection reports configuration only, not authentication. Tool annotations alone do not establish safety. An absent or malformed mapping cannot invent an operation, and an unknown or partial dependency result cannot establish a complete dependency set.

Neuve owns the mapping and normalized planning results. The user-run external OAuth bridge owns its consent, refresh, revocation, and token store. Neuve stores no bridge token. Background planning reads never initiate interactive consent. Reconnection remains an explicit operator action, separate from Neuve's ChatGPT subscription sign-in and provider credential owner.

The [Linear integration status](../../docs/development.md#linear-planning-integration) records that real-account setup and the Ace planning entry wait only on the owner's Linear sign-in. Selection passes the chosen integration and issue to source-selected Records admission. The [existing cycle snapshot](../../packages/harness/src/scope.ts) keeps source attribution, fetch time, excerpt identity, and freshness behavior. Later issue edits do not replace that cycle's excerpt; changed requirements belong to the existing freshness and next-cycle rules. Records remains the authority for review facts and dispositions. Linear remains the only workstream scope authority, without a standing local ticket mirror.

## Development and completion

The transition's canonical clone, Git common directory, implementation worktrees, large state, artifacts, caches, and temporary output live on an external LaCie volume. Its workspace launch scripts check the intended volume and refuse an unavailable location rather than creating an internal fallback. Production storage remains explicitly configurable for other users and machines. The current HFS+ volume requires Bun's `copyfile` install backend.

Workstreams use separate external worktrees with disjoint ownership. Each has an implementer and an independent reviewer. The coordinator alone integrates reviewed commits into `codex/pi-transition`. This supersedes the former shared-checkout and no-worktree operating restriction for this transition. Run the required checks and converging runtime validation before handing the integrated branch to the owner. The owner's full run is a separate gate before any merge to main.

This record supersedes the Effect-only execution choice in [0003](0003-effect-native-harness-runtime.md). The [six-layer ownership record](0001-layers-and-responsibilities.md) continues to govern Records, Graph, CLI, MCP, and the web app.
