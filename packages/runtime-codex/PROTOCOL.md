# Codex app server: the facts the runtime relies on

**The design this table was first written for was replaced.** It was written to support a check at session open: read back from the running program its configuration, features, hooks, skills, MCP servers and apps, and refuse the session unless only Neuve's tools were left. The finding below stands as a fact. On 20 November 2026 the owner ruled that Codex keeps its own tools, as T3 Code has it ([the decisions record, Area 14](../../process/decisions.md#area-14-lane-assignment-and-agent-dispositions-redesigned-12-november-2026); the [Codex runtime proposal's tools section](../../process/proposals/codex-runtime.md#tools-codex-keeps-its-own-and-neuves-are-served-beside-them) follows it). So the check at open is dropped, and no revision of it is being chosen here.

The finding: at 0.171.0-alpha.13 every read-back reflects the command line, and each of the person's own settings can be switched off and is read back off. But OpenAI's source at this release registers tools for the model that none of the read-backs names:

- **File editing.** `apply_patch` is registered whenever the model's catalogue entry names a patch format ([`spec_plan.rs` line 1483](https://github.com/openai/codex/blob/rust-v0.171.0-alpha.13/codex-rs/core/src/tools/spec_plan.rs#L1483)). No feature gates it. In Codex's model cache on this machine, read once during this work and not kept, each of the three models read names the `freeform` format.
- **Tools the catalogue entry declares.** Its `experimental_supported_tools` adds more (lines 1386, 1414, 1442 and 1490).
- **Asking the user.** `request_user_input` is registered unless `tools.experimental_request_user_input.enabled` is set to false, and it is on when unset, whatever the catalogue says ([`spec_plan.rs` lines 1373–1380](https://github.com/openai/codex/blob/rust-v0.171.0-alpha.13/codex-rs/core/src/tools/spec_plan.rs#L1373); [`config/mod.rs` lines 2871–2877](https://github.com/openai/codex/blob/rust-v0.171.0-alpha.13/codex-rs/core/src/config/mod.rs#L2871)).
- **Codex's MCP-resource tools** (list and read a server's resources) are added whenever any MCP server is configured, or in code-mode-only operation ([line 1329](https://github.com/openai/codex/blob/rust-v0.171.0-alpha.13/codex-rs/core/src/tools/spec_plan.rs#L1329)).

The plan tool is not among them: it is off by default, registered only when `tools.update_plan.enabled` is true ([`spec_plan.rs` line 1357](https://github.com/openai/codex/blob/rust-v0.171.0-alpha.13/codex-rs/core/src/tools/spec_plan.rs#L1357); [`config/mod.rs` lines 2879–2885](https://github.com/openai/codex/blob/rust-v0.171.0-alpha.13/codex-rs/core/src/config/mod.rs#L2879)), which the launch configuration does not set: the kept recording reads back `tools: null`.

Traced: where tools are registered (`add_core_tool_sources`, called from `build_tool_router`, line 151) and the final filters (`finalize_tool_router`, line 401), which change what is visible only in code-mode-only operation or through a tool policy that a client cannot supply (below). No thread was started and no model turn was run in the slice's recorded runs. One short turn was run afterwards, on 20 November 2026, asking the default model to list its tools; it has no committed recording, so what it showed is marked below as observed, not proved.

## How the program was found and run

By the design's probe order applied by hand. The applications folders were read for the identifier `com.openai.codex`, and the app that carries it was used. Its `codex-package.json` has layout version 1, version `0.171.0-alpha.13`, target `aarch64-apple-darwin`, and entry point `bin/codex`, which is exactly the program in the package's own `bin` folder after links are followed (T3 Code's rule, `apps/server/src/provider/CodexInstallation.ts` line 255). A few lines of script printed that path, which each run took as `--program`. The handshake's version matched the manifest's.

Each run was `<program> app-server [-c key=value ...]` with the transport on standard input and output, through [`scripts/record.ts`](scripts/record.ts). Each had a new empty working folder under the temp directory, `CODEX_HOME` set to the person's own Codex home, and OpenAI's key and address variables removed (`REMOVED_ENVIRONMENT` there). Five runs. ## The session's states

A session holds at most one Codex process. Its state is four facts, and the code that changes them is one function, `ensure`, with one place a process starts (`startProcess`) and one that stops them all (`stop`, then the finalizer).

| Fact                | Values                                                                                                                                                                | Changed by                                           |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| The current process | none, or one process that has answered its handshake at a version not marked broken, passed the clean check when it is clean, and loaded the thread when there is one | `ensure`, only after all of those succeed            |
| Its configuration   | the person's own Codex, or clean                                                                                                                                      | the same                                             |
| The open turn       | none, or one turn, open until its one `turn.finished`                                                                                                                 | `startTurn`, `finish`                                |
| The session         | live, or stopped                                                                                                                                                      | `stop`, on a death, a broken turn or the scope's end |

The rule that keeps these consistent, and that the defects of the third review each broke:

- **A process becomes current only after its check and its resume succeed.** Until then it is only in the set of processes the session started. If any step fails, or the start is abandoned, that process is closed and no process is current, so the next turn starts over: a new process, checked, with the thread resumed. A read-only turn can therefore never run where the clean check did not finish, and no turn is sent to a process that never loaded the thread.
- **One process at a time.** The current process is closed before the next starts, the short-lived one that reads the person's setting names included. This removed the earlier case of a refused clean start leaving the old process serving: a refusal now leaves none, and the next write turn restarts the person's Codex. It costs one restart after a refusal.
- **After every wait, the session and the turn are re-checked before anything is written.** Closing a process, reading the settings, starting a process, the clean check and the resume each end in that check, and `turn/start` is written only to the current process of a live session for a turn that has not ended.
- **No process starts once the session is stopped,** and every process the session started is closed when it stops. The finalizer closes and waits for every process still in the set, whether or not a death or a broken turn stopped the session first. A start that a stop overtakes is closed by that stop, since its process is already in the set.
- **The death of a process that is not current is not the session's.** One that dies while it is being prepared fails its own pending request, and the code preparing it closes it.
- **The person's setting names are read again at each clean start,** so a server they added since the session opened is switched off by name too; the clean check also reads each of their servers' switch, not only whether it lists tools, since one that failed to start lists none either.

The work a piece of Codex's own work returned (a command's output, a file change's diff, another server's result) is bounded where the runtime reads it, to 64 KiB with its start and end kept, since the event, the transcript and the log each carry it.

## How a turn ends

The runtime's session ([`src/session.ts`](src/session.ts)) is built from this table and holds two invariants: **every started turn has exactly one terminal event**, and **no Codex turn is left running that Neuve does not track**. Every row goes through one function, `finish`, which emits the turn's one `turn.finished` and ignores every later source, so two sources of one ending (an `error` notice and then `turn/completed`, or a stop and the death it causes) still give one event.

Every cancellation goes through one mechanism: **a deadline that starts when the interrupt arrives** (ten seconds) and, if the turn has not ended by then, ends it interrupted and stops the process, whatever Codex has or has not answered. Beside it, `turn/interrupt` is sent as soon as Codex has named the turn, by its answer to `turn/start` or by `turn/started`. That one mechanism covers a request Codex never answers, an abandoned start and an interrupt before the turn is named.

| How the turn ends                                                                                                        | What `turn.finished` carries                                                                                                                                               | The session after it           |
| ------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------ |
| `turn/completed`, `completed`                                                                                            | `completed`, resume point Codex's turn id                                                                                                                                  | open                           |
| The same, on a final turn                                                                                                | `completed` with the last agent message parsed as JSON; with no message `structured-output-missing`, with text that is not JSON `structured-output-invalid`, both reusable | open                           |
| `turn/completed`, `interrupted`                                                                                          | `interrupted`, with the reason `interruptTurn` gave                                                                                                                        | open                           |
| `turn/completed`, `failed`, `unauthorized`                                                                               | `SignInRequired`, hint `codex login` (with `CODEX_HOME` when the account names a home), reusable                                                                           | open                           |
| The same, `usageLimitExceeded`                                                                                           | `UsageLimitReached`, with the window from the last rate-limit update, reusable                                                                                             | open                           |
| The same, `contextWindowExceeded`                                                                                        | `context-overflow`, reusable                                                                                                                                               | open                           |
| The same, an overloaded, unreachable or failing service                                                                  | `provider-unavailable`, reusable                                                                                                                                           | open                           |
| The same, anything else                                                                                                  | `provider-failed`, reusable                                                                                                                                                | open                           |
| An `error` notice with `willRetry`                                                                                       | no ending: a `retry` event, and the turn goes on                                                                                                                           | open                           |
| An `error` notice without it                                                                                             | no ending of its own: its reason is used if `turn/completed` names none                                                                                                    | open                           |

| `interruptTurn`, and the turn has not ended by the deadline, counted from the interrupt                                  | `interrupted` first, then the process is stopped                                                                                                                           | ended                          |
| `turn/start` that Codex never answers, then `interruptTurn`                                                              | the deadline: `interrupted`, the process stopped                                                                                                                           | ended                          |
| The `thread/resume` after a change of mode that Codex never answers, then `interruptTurn`                                | the same                                                                                                                                                                   | ended                          |
| The caller abandons `startTurn` before `turn/start` is written                                                           | `interrupted` at once; a process half started for it is closed                                                                                                             | open                           |

An approval still open when its turn ends is answered as declined. A call to one of Neuve's tools still running is reported as `tool.finished`, errored, before `turn.finished`, and then aborted; it is taken out of the turn first, so a handler that resumes on the abort does not report it again. Codex's own work that started and never completed is reported once, as not finished. Sign-in is also asked of Codex at open (`account/read`): signed out, the session is refused with `SignInRequired` and no turn starts.

## What the protocol log keeps

Every line each way, redacted as it is written ([`src/log.ts`](src/log.ts)): Codex's own commands, their output and file changes, and calls to Neuve's tools, whole, since they are the run's record of what was done. Not kept: streamed text (its length only), the person's configuration and skill list (their size only), their plan and balance, the operating system's release, and every MCP server's name but Neuve's. A call to one of the person's own servers keeps its tool's name and its status, and loses its arguments, result and error, which are theirs. The session's token, folders and program, and the names of the person's settings, are replaced by labels wherever they appear.

## What the runtime slice closed, and what stays open

- **Responses are decoded where the runtime reads them**, by [`src/decode.ts`](src/decode.ts): only the fields read, the rest passed through. A turn's ending that does not decode ends the turn; an item that does not decode is logged and skipped.
- **The notification queue is bounded** at 200,000 unread (`MAX_QUEUED_NOTIFICATIONS`); past it the connection ends with `CodexBacklog`.
- **A refused write ends the connection** with `CodexInputRefused`: what was not written is lost.
- **Neuve's server is named `neuve`**: a server of the person's under that name would take its place, so a session that serves Neuve's tools is refused when the person has one. In a session that serves none, a server named `neuve` is the person's like any other: its calls are their work, and the log drops their arguments.
- **Every line reaches the caller** through `onLine`, which the protocol log and the recorder both use; the recorder no longer frames lines itself.
- **Still open: replay matches method names only**, and **two feature lists**: the clean session's list of personal features is the runtime's own (`PERSONAL_FEATURES` in [`src/launch.ts`](src/launch.ts)), beside the recorder's and the replay judge's.

## What the generated types keep, and leave out

[`scripts/generate.ts`](scripts/generate.ts) takes OpenAI's published TypeScript at the tag (the stable surface: the experimental methods and fields are not in it), fetched at the commit the tag resolves to, which each file's header records; it refuses to regenerate from the same tag at another commit unless told to repin. It keeps 327 files: 20 client requests (`thread/fork` added for the runtime), 23 notifications, and every server request with the answer it takes where the schema names one (`ServerResponses`), with what they import. It leaves out the other notification types (their names stay in `SERVER_NOTIFICATIONS`, so a known one is never mistaken for an unknown one), the other client requests, the JSON Schema form, the legacy `v1` folder and the precomputed export lists. Adding a method to its lists and running it again brings that method in.
